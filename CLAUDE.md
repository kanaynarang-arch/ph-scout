# Rules for working on ph-scout

- Gemini Flash only (through @google/genai). No Claude or other AI provider: no package, env var, import or API call.
- Secrets live only in env vars (PH_API_TOKEN, GEMINI_API_KEY, GEMINI_MODEL, DATABASE_URL, CRON_SECRET, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, RESEND_API_KEY, NOTIFY_EMAIL, NOTIFICATIONS_ENABLED) and are never committed.
- The tool never contacts founders, never looks up emails or contact details and never sends outreach. "Find contact yourself" is only links (a LinkedIn people search and a web search) built in the browser from names already on screen; it fetches and stores nothing. When Kavya clicks Generate it also sends a copy of the list to her own Telegram and email. A human (Kavya) does all outreach. The Draft message button asks Gemini Flash for a first message that Kavya edits and sends herself: that call gets only public launch text and the saved angle (never maker names; the page fills in the founder's first name from what is already on screen), returns text only, and nothing is ever sent.
- (The "real Generate click" check is header-based, a convenience boundary that a client could forge; the 1-per-5-minutes limit to Kavya's own recipients is the real protection.)
- The page has Telegram and Email switches (both on by default, remembered in the browser). They are sent as `channels` and can only switch a channel that the server already has configured OFF for that Generate: recipients, channels and text never come from the page, malformed input is ignored, and with both off nothing is sent and no send slot is used.
- The copy to Kavya is sent ONLY by a real Generate click (never Refresh now, /api/refresh, page load or the GitHub Action), only to the recipients in server env vars, never to anyone else, and is limited to one per 5 minutes. Switch it off by unsetting NOTIFICATIONS_ENABLED.
- Optional extra categories are off by default, come only from the fixed menu in lib/categories.ts (at most 2), and are accepted only as ids from a same-origin browser request: the client never supplies Product Hunt topic names. The four built-in categories are always scanned.
- All numbers are computed in code. Gemini writes language only (fit label, one-liner, outreach angle, quote). Rank = score from upvotes and maker comments only.
- Only public launch text goes to Gemini. No maker or commenter names or IDs.
- Neon stores only public Product Hunt launch data, maker-comment counts, Gemini outputs, first-seen launch ids, and the send limits (one control row; never message text, tokens or addresses).
- The app must work with no DATABASE_URL and with Neon down (it then fetches live every time, and falls back to the bundled snapshot labelled SAMPLE).
